? 209.0 Здесь мы подробно рассмотрим метод «createEntityAdapter», который можно подключать опционально, чтобы оптимизировать работу и облегчить некоторые операции.

Рассмотрим этот метод в мини-приложении «Hero Admin Panel»: [projects/hero-admin-panel/src/components/heroesList/heroesSlice.js]

? 209.6.0 Теперь, если перейти в браузер и вкладку расширения Redux Devtools, то мы увидим, что у нас есть в стейте собственно "heroes" в котором массив "ids", с перечисленными значениями "id", взятыми из объектов героев (значения их поля "id"), а также там объект с объектами "entities". И одна небольшая неприятность заключается в том, что раньше объекты героев были в массиве и мы совершали именно с массивом какие-то действия. Получилось так, что нормализация здесь сыграла с нами шутку. Конечно, можно было бы написать функционал, переводящий эти данные обратно в массив, но разработчики Redux Toolkit за нас это уже продумали. Я уже написал выше, что объект-адаптер содержит не только CRUD-методы, которые как-то изменяют данные, но и селекторы (специальные функции, что получают какие-то кусочки глобального store). В добавок они уже будут мемоизированы. Например:
* селектор `selectIds` вытащит объект со всеми ID;
* селектор `selectEntities`, но он вернёт сущности из объекта "entities" не массивом, а объектом;
* селектор `selectAll`, который и подойдёт нам в этом случае, вернёт собственно те же сущности из поля "entities", но уже массивом;
* селектор `selectTotal` - вернёт число, общее кол-во сущностей, находящихся в этом стейте;
* селектор `selectById` - вернёт какую-то сущность через её ID, с ней связанным.

? 209.6.1 Итак, как же использовать эти селекторы. Напрямую, обращаясь к адаптеру, как в случае с методами, мы их использовать не можем. Чтобы применить селекторы, нам нужно сперва их получить через метод адаптера "getSelectors". По сути, она просто вытащит селекторы из этого адаптера. И в примере ниже два способа использования этого метода:
<script>
import {configureStore} from '@reduxjs/toolkit'; 

const store = configureStore({
    reducer: {
        books: booksReducer,
    }
});

/* 209.6.2 Простые селекторы: Запускаем метод "getSelectors", чтоб получить объект с селекторами. */
const simpleSelectors = booksAdapter.getSelectors();

/* 209.6.4 Глобализированные селекторы: Ещё один вариант, но более специфичного селектора. Здесь мы внутри метода "getSelectors" мы сразу получим стейт и затем выберем какую-то часть из него. ↓ */
const globalizedSelectors = booksAdapter.getSelectors((state) => state.books);

/* 209.6.3 Обращаемся к объекту с селекторами выбираем нужный метод (например "selectIds" и вызываем его). Однако в таком варианте нет привязки к какому-то кусочку стейта, селектор не знает с чем он работает и мы можем вызвать его с чем угодно. Поэтому внутри метода мы обращаемся к store, получение из него стейта и потом ту часть стейта "books" (с каким слайсом), с которой должен поработать этот метод. (На мой взгляд не слишком удобно.) ↑ */
const bookIds = simpleSelectors.selectIds(store.getState().books);

/* 209.6.5 Здесь уже мы можем более лаконично записать вызов метода "selectAll". */
const allBooks = globalizedSelectors.selectAll(store.getState());
</script>
