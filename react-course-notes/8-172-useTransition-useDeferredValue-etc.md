*[Хуки «useId», «useTransition», «useDeferredValue» и другие нововведения React 18 (172)]*

? 172.0 Продолжим рассмотрение нововведений с 18-ой версии Реакта и теперь у нас на очереди несколько полезных хуков.
172.1.0 Начнём с «useId» — он создаёт уникальные идентификаторы, вроде того, как это делали сторонние библиотеки. Просто вызываем хук на ту переменную, в которую хотим записать уникальный ID. Однако, в документации стоит, что не стоит его применять для атрибута "key" в рабочих проектах, т.к. эти атрибуты должны браться из данных БД.
172.1.1 Также интересный момент, что можно эти ID использовать для формирования вёрстки, чтобы убедиться, что их название будет уникальным, но тогда их нельзя будет использовать как CSS-селектор или получать браузерным API вроде метода "querySelectorAll".
<script>
const id = useId();

return (
    <div>
        <label htmlFor={id + '-firstName'}>First Name</label>
        <input id={id + '-firstName'} type="text">        
        <label htmlFor={id + '-lastName'}>Last Name</label>
        <input id={id + '-lastName'} type="text">
    </div>
);
</script>

172.2 Также добавились несколько специфичных хуков для разработчиков сторонних библиотек, например «useSyncExternalStore» & «useInsertionEffect», но нас сейчас они мало интересуют.

172.3.0 В 18-ой версии Реакта вводится т.н. «конкурентный режим» и с точки зрения нас, как фронтенд-разработчиков, особенно ничего не меняется, но под капотом Реакт стал работать иначе в плане рендера компонентов. Он может выполнять сразу несколько рендеров или ставить их на паузу, отдавая приоритет чему-то определённому и некоторые другие определённые процессы.
// 172.3.1 Рассмотрим на примере: Представим пользователя, который что-то быстро печатает в поле поиска и на основе ввода происходит фильтрация товаров. В более старых версиях Реакт по каждой введённой букве обновлял бы компонент с товарами, что приводило бы к морганию интерфейса, да и в целом не слишком оптимальному использованию ресурсов. Теперь же он будет пытаться оптимизировать этот процесс, откладывая рендер каких-то компонентов, например, ререндер поля поиска сейчас, а товары с небольшой задержкой. Для таких случаев и нужен «конкурентный режим».
// 172.3.2 Для управления «конкурентным режимом» были введены два новых хука «useTransition» и «useDeferredValue», чтобы создавать переходы. (Они используются обычно при работе с большими объёмами данных и ресурсозатратными операциями поиска или фильтра. Но также можно применить и на динамические подсказки или табы, показывая при помощи "isPending" пользователю спиннер.)

Рассмотрим как это работает на примере: [\projects\react-project-1\src\ConcurrentModeExample.js]
